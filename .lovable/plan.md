# AeroQuote Compass — ERP reorganization

Goal: reorganize navigation and interface into a professional ERP structure, preserving all existing calculations, business rules, tests, the SIGNAL & STRUCTURE visual identity, and synthetic-data labelling. `rules.ts` and all deterministic libs stay untouched; new logic goes in pure tested modules under `src/lib/rfq/`.

Delivered in three rounds; after each round the full test suite runs and layouts are checked at 320–1440px.

## Round 1 — ERP shell, dashboard and RFQ record

- **Collapsible sidebar** (grouped, icon + label, tooltips when collapsed, mobile drawer): Dashboard; RFQ record; Quotations; Supplier Comparison; Decisions; Purchase Orders; Release Control; Traceability (Configuration, Audit Trail, Investigations); History/Settings.
- **Global header**: breadcrumb, current RFQ + process status, notifications (attention items), contextual help, fictional demo user, and **global search** over the loaded RFQ: suppliers, quote IDs, part number, PO numbers, drawings, revisions — pure `search.ts` with tests.
- **ERP dashboard** as the new landing view: open items, quotes awaiting validation, POs awaiting check/blocked, new revisions, expiring quotes, pending decisions, open investigations, and a "Requires attention" list ordered by severity with process / reason / owner / due / severity / next action, each linking straight into the flow. Reuses and extends pure `operations.ts`.
- **RFQ as a central record**: header with RFQ number, description, part number, current revision, annual quantity, base currency, owner, status, created/updated; internal tabs Overview / Quotations / Buyer Validation / Comparison / Decision / Purchase Order / Release Control / Documents / Activity — replacing the current step strip as the single navigation (no competing tab sets). The existing six-step content is mapped into these tabs unchanged.
- **Compact 8-step process stepper** (RFQ created → Quotes received → Buyer validation → Comparison complete → Decision approved → PO issued → PO verified → Released) with status, date, owner, blockers and details link; states Not started / In progress / Requires attention / Blocked / Completed with icon + text (never color only). Pure derivation layered on `workflow-stages.ts`, with tests.
- One evident primary action per screen; blocked actions explain why and how to unblock.

## Round 2 — Purchase Order lifecycle and issued-PO document

- **Explicit PO state machine** (pure `po-lifecycle.ts` + tests): Draft → Generated → Issued → Awaiting verification → Requires correction / Blocked → Verified → Awaiting release → Released; plus Superseded and Cancelled. Status shown on PO list, PO header, preview, RFQ record, timeline and dashboard.
- **Explicit PO sequence** in the Purchase Order tab: PO draft → generated → issued → verification → discrepancy review → revision verification → ready for release → released, clearly separating create / issue / check / approve discrepancies / release.
- **Issued PO document preview**: professional synthetic commercial document with buyer company header, PO number, issue date, status, currency, buyer, RFQ/quotation references; supplier block; ship-to/bill-to, delivery date, shipping method, freight terms; line items (line, part number, drawing revision, description, qty, UoM, unit price, line total, delivery); additional costs (freight, insurance, NRE, tooling, taxes, other); totals; technical & quality requirements (drawing/spec references, certifications, inspection, quality clauses, required documentation); approval & traceability (decision reference, approved supplier, approved landed cost, generated by, approval date, PO Check status, release status, audit reference). Banner: "Synthetic demonstration document — no commercial validity." Pure `po-document.ts` builder + tests.
- **PO viewer**: document preview with zoom, print, PDF export, download, fullscreen, return to PO Check; desktop document-left / summary-right; mobile summary + actions + "View issued PO" with zoom and a structured section view (no illegible shrunk A4).
- **Decision → PO provenance**: per field show reviewed quote value / approved value / PO value / difference / source / approver; divergences highlighted with expected vs found, financial impact, severity, required action; never silently corrected.
- **Draft editing**: draft clearly marked, required-field validation, unsaved-changes indicator, save + audit; editing locked after issue — later changes create an amendment/PO revision, never a silent overwrite.
- **PO list screen**: search, filters (status, supplier, buyer, date, currency, blocked, awaiting verification/release), sorting, pagination, column selection, export; columns PO number, RFQ, supplier, issue date, amount, currency, verification/revision/release status, buyer, last update.

## Round 3 — Consistency, UX writing, error prevention, final verification

- Consolidate design-system tokens and standardize buttons, inputs, tables, cards, modals, drawers, tooltips, badges, alerts, breadcrumbs, steppers, empty states, skeletons, error messages — keeping the current AeroQuote identity, elevated to ERP finish.
- UX writing pass: objective verb labels (Create, Upload, Validate, Compare, Approve, Generate, Issue, Check, Request correction, Release); messages explain what happened, why, how to fix, what happens next.
- Error prevention: confirmations for irreversible/bulk actions, inline validation, preserved input, double-submit prevention, loading states, explained disabling, unsaved-changes indication.
- Accessibility: semantic HTML, keyboard navigation, visible focus, focus trap/return in modals, WCAG AA contrast, aria-live status, labelled icons, color-independent states.
- Final verification per the brief: full flow (create RFQ → 20 quotes → validate → compare → approve → generate/issue PO → view issued PO → correct/divergent/blocked POs → revision & traceability → release), search and filters, keyboard, all breakpoints 320–1440, 200% zoom; fix anything found.

## Technical notes

- New pure modules with unit tests: `search.ts`, `po-lifecycle.ts`, `po-document.ts`, stepper derivation; `operations.ts` extended for the dashboard attention list. No business logic in components; no changes to `rules.ts`, scoring, landed-cost or PO-check engines.
- Routing: TanStack routes for `/` (dashboard), RFQ record tabs and PO views; existing history/save and exports keep working; all 287 existing tests must keep passing.
- All data remains clearly labelled synthetic; PO document carries the no-commercial-validity banner.
